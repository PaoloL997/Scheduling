# Technical debt

- ui/services/inventory.py `update_resource` (PUT `/api/inventario/<table>/<uid>/`, sent by the detail modal in ui/templates/ui/inventario.html): renaming a `uid` does not rename the row. `uid` is the primary key of the five inventory models, and the function sets the new value on the loaded instance and calls `obj.save()`, so a free new uid inserts a second row and leaves the old one, and a uid owned by another item overwrites that item with no error; the `IntegrityError` → "già presente" branch never fires. Write through `model_class.objects.filter(uid=original_uid).update(...)` as `patch_resource` does in the same file, and add a rename test and a collision test to ui/tests/test_inventory_api.py.

- ui/views.py `_serialize_log_entry`: `entry.timestamp.strftime("%d/%m/%Y %H:%M")` formats an aware UTC datetime (`USE_TZ = True`, `TIME_ZONE = "Europe/Rome"` in config/settings.py), so every row of Impostazioni → Log is one or two hours behind the wall clock. Format `django.utils.timezone.localtime(entry.timestamp)` instead.

- ui/views.py `api_inventario_add` and `api_inventario_detail`: the HTTP status is picked by searching the Italian text of the `ValueError` raised in ui/services/inventory.py (`"già presente" in str(exc)`, `"non trovato" in msg`). On PUT every other message becomes 404 and on POST every message becomes 409, so "Valore booleano non valido" or "La manutenzione è disponibile solo per Testa e Generatore." answer 404/409 instead of 400, and rewording a message silently changes the status. Nothing in ui/services raises `RuntimeError`, so the four `except RuntimeError` → 503 branches and the "503 when the database is not yet available" docstring lines are dead. Raise typed exceptions (duplicate, not found, invalid) from inventory.py, map them to 409/404/400 in the view, and drop the 503 branches.

- ui/views_ottimizzazione.py `api_ottimizzazione_spiegazione` and `api_ottimizzazione_accetta`: the final `except Exception:` returns a generic 500 ("Errore durante l'applicazione della proposta.", "Errore durante la generazione della spiegazione.") without logging anything, so an unexpected failure while applying an accepted optimization leaves no trace.
