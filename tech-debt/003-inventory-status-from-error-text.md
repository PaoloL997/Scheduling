# Inventory endpoints pick the HTTP status from the error text

ui/views.py `api_inventario_add` and `api_inventario_detail`: the HTTP status is picked by searching the Italian text of the `ValueError` raised in ui/services/inventory.py (`"già presente" in str(exc)`, `"non trovato" in msg`). On PUT every other message becomes 404 and on POST every message becomes 409, so "Valore booleano non valido" or "La manutenzione è disponibile solo per Testa e Generatore." answer 404/409 instead of 400, and rewording a message silently changes the status. Nothing in ui/services raises `RuntimeError`, so the four `except RuntimeError` → 503 branches and the "503 when the database is not yet available" docstring lines are dead. Raise typed exceptions (duplicate, not found, invalid) from inventory.py, map them to 409/404/400 in the view, and drop the 503 branches.
