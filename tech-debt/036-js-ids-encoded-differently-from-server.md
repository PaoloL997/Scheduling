# Activity and job ids rebuilt in JS differ from the server ids

ui/templates/ui/pianificazione.html `_enc`, `buildJobId`, `buildActivityId` (used by `_wizAppendRow`, the save toast and the detail panel): ids are rebuilt in the browser with `encodeURIComponent`, which leaves `! ' ( ) *` unescaped, while the server builds them with `quote(value, safe="")` in ui/services/identifiers.py. For a commessa or an activity type such as "Saldatura (TIG)" the new row's `data-activity-id` differs from the server id until the page is reloaded, so the detail panel's self-exclusion (`a.activity_id !== originalData.activityId`) fails and the activity is offered as its own predecessor. Use the `activity_id` and `job_id` returned by the save responses (`task`, `job`) wherever a server id exists, and keep the JS builders only where none is available yet.
